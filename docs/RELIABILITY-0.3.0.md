# 异常处理与设备识别（v0.3.0）

## 音频资源

启动、停止、释放和监听切换的生命周期操作串行化。停止请求取消所有线程，音频线程共用最多 4 秒的等待预算；一个线程超时后仍尝试其他线程与监听的清理。全部退出后才释放等待句柄和取消源，并标记已释放。未完成清理时保留资源引用和错误状态，允许复位或退出重试，不强行终止卡在驱动内的线程。

监听清理失败同样保留引用。系统关闭时若清理失败，错误被记录，本次可取消的关闭被取消，窗口和托盘恢复供重试；清理成功后才进入关闭状态。偏好保存错误单独记录。系统强制结束进程不受应用控制。

## 配置与安装状态

用户设置缺失、损坏、空对象、占用或读取权限被拒绝时使用默认配置继续启动；读取失败本身不覆盖原文件。主界面保存失败会即时显示所选语言的提示。安装状态缓存异常也记入日志，不阻断健康驱动；成功安装记录与旧未确认记录的处理见 [启动检查](STARTUP-INSTALL.md)。

## 设备身份

启动检查、输入/输出列表和监听限制共用 AudioDevice.IsCable。通过内置 INF 的硬件 ID/服务和实际 PnP 节点识别基础版 VB-CABLE，端点显示名、其他 VB-Audio 产品名称和注册表残留都不充当证明。

逐设备隔离查询失败，可选显示信息读取失败不丢弃已确认身份。与基础驱动关联的硬件/服务/状态错误保留为检测失败；无关设备错误不阻断修复。完整规则见 [启动检查与驱动安装](STARTUP-INSTALL.md)。

两级模型、推理参数、增益/限幅、重采样算法和播放缓冲策略保持原样。当前检查见 [VALIDATION.md](VALIDATION.md)，维护条目见 [MAINTENANCE-20261115.md](MAINTENANCE-20261115.md)，早期测量见 [历史记录](HISTORICAL-VALIDATION.md)。
