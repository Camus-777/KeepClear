# 启动检查与驱动安装（v0.3.3）

主界面仍为 480×456 逻辑尺寸、四个按钮及三组设备选择；启动界面保留白底、黑字 KeepClear 和蓝色光标，480×280 逻辑尺寸。首次启动动画打字约 1.8 秒；每次点击“开始自检 / Run test”会从头重播，打字时间约 2.6 秒。文字输出完而检查未结束时光标持续闪烁；即使检查立即完成，也会播完打字并完成约 0.45 秒收尾再进入主界面。

## 麦克风选择

每次主 GUI 启动先核对 worker、Focus/Cue/DNS48 文件及 SHA256、基础版驱动状态，之后显示麦克风选择框、刷新键、“开始自检 / Run test”和退出键。下方明确提示开启麦克风，并取消声卡或耳机静音。此时不会打开麦克风音频流或加载模型进程。

上次选择仍有效时预选，但每次都需要确认。未保存选择或设备消失时保持未选择，不自动替换为默认/首个麦克风。确认后只测试该端点 ID，检查失败可刷新/更换后重新确认；设备失效不会偷偷换麦克风。确认选择尝试保存；若配置写入失败，本次仍使用所选设备并在主界面提示无法保存。

通过后主界面的麦克风严格沿用该 ID；自检与进入主界面之间若断开，则保持未选择并提示设备缺失。主界面不会因为自检结果改选其他麦克风。用户以后主动更换设备仍使用原有主界面操作。托盘恢复、第二进程激活不会重复完整自检。

## 实际静音链路与连通性

确认后加载一次 Alkove Focus → Denoiser DNS48，复用现有采集、重采样、增益/限幅和输出线程，并读取同一基础 VB-CABLE 节点的录音端。只要求四段实际进展：麦克风已采集数据、双模型已返回样本、处理后样本已成功提交给 WASAPI 输出，以及匹配的 CABLE 录音端有回读。四项满足就通过，不另设固定的性能观察时长。

欠载次数、采集间断、单块或平均耗时、队列水位以及回读速率不决定测试成败；取消旧的 2.5 秒性能观察和二次恢复复查。仅在这项静音测试中，有限容量的输入/输出缓冲拥堵时保留较新的测试样本，不因队列拥堵报性能失败；正式运行使用单独的趋势恢复策略，见 REPAIR-0.3.3.md。

权限拒绝、设备无法打开/断开、模型异常或链路始终无响应仍会提示。音频阶段总上限 45 秒，模型初始化/单次推理仍分别受 45 秒/2 秒保护，设备等待上限不变。正常运行中不重复做完整自检。环境、权重完整性、驱动识别/安装、麦克风确认和动画流程均不调整。

所有测试输出使用 WASAPI SILENT 标记；不向游戏/通话发送本软件采集的人声、不启动监听、不保存录音。它核验的是接口与处理路径能运行，不证明持续实时性能、主观音质、非零语音内容贯穿驱动或游戏实际选中的麦克风。其他应用写入 CABLE 的声音不受 KeepClear 控制。

Windows 可报告的静音仅提示，不自动取消；物理静音若只产生全零输入，与安静环境无法区分，允许通过。界面的开启提示不代表程序能验证所有实体开关。

## 驱动识别、无关设备与安装等待

从内置官方 vbMmeCable64_win10.inf 提取硬件 ID VBAudioVACWDM、服务 VBAudioVACMME；通过 Media 类 PnP 节点及 Windows 端点拓扑匹配实际基础版驱动。设备名、注册表残留和非唯一容器 ID 不充当安装证据。健康的不同版本可以直接使用，不强制降级；Voicemeeter、CABLE A/B 不充当基础版。

无关端点的身份查询错误只记日志，不阻断不完整基础驱动的修复。明确关联基础驱动节点的身份查询失败仍报检测错误，不猜测身份。枚举 Media 节点时，无关硬件不再读取服务/版本等修复无关属性。

缺失或不完整时，通过官方原包请求一次 runas 安装；全局互斥量和安装进程检查防止并发启动。原包和安装 EXE SHA256 分别固定为 bc44e8974191a5a2427d6c979e2dab08dbb09925f3f435dfa2f0ba3e45b6eb90、734c35dfa6d98f48782a451633ceb471166ec70d60482fd89a1123d0ee3c4f41；参数 -i -h，保留原包许可。

安装程序退出后最多等待约 20 秒让端点就绪，可用即继续。返回 0 但端点未出现时显示“安装已结束，虚拟声卡尚未就绪”，提供重新检查、重启电脑和退出；不冒充成功、不直接归为安装失败。重新检查仅继续等待，不重复安装。非零错误显示实际失败；3010/1641 或 PnP 需重启标记进入明确重启提示。所有重启按钮都先确认，不强制关闭其他应用。

仅在安装程序确认成功退出后，才将完成标记和待就绪/需重启记录写到 LocalAppData/KeepClear/driver-setup/install-state.xml；安装前不写成功记录。旧版未区分启动前后阶段的记录会先做一次有限等待，仍未就绪且没有安装进程时允许一次修复。已确认完成的记录仍防止同一次开机内重复安装。记录损坏、锁定或权限错误写入诊断日志，不阻断健康设备的使用。依据系统运行时长估计 Windows 启动时间，容差 2 分钟；明显调整系统时钟可能影响估计。设备就绪会清理记录，重启后重新按真实设备状态判断。取消 UAC 或明确失败允许用户主动重试；安装程序进行中不会被本程序杀掉。明确禁用设备只提示启用，不自动重装。

## 中英文错误与诊断

权限拒绝、设备占用、断开/失效、所选麦克风不可用、模型加载、模型处理、速度不足、输入/输出超时、回读失败及格式问题分别提供中英文标题和处理建议；分类以错误类型、阶段及 HRESULT 为依据，不匹配操作系统报错文字。权限拒绝不声称已经确定是某个物理开关或单一隐私选项。语言切换即时翻译，不重复检查。

文本日志位于 %LOCALAPPDATA%/KeepClear/logs，记录阶段、设备身份、HRESULT、安装退出码、队列、恢复次数及吞吐；不含音频。错误提示悬停可查看详细原因和目录，点击可打开日志。日志写入失败不会使程序退出。默认英文及用户保存的语言选择不变。

## 命令与验证范围

- `--check-startup <report.txt>`：只读依赖/驱动/内存双模型检查，不打开麦克风、不安装驱动。
- `--check-audio <report.txt> "<endpoint-id>"`：明确指定麦克风后进行真实静音链路检查，不安装驱动。省略 ID 返回 select-microphone，不自动选设备。
- `--self-test <report.txt>`：仅合成音双模型，不打开设备。
- `KeepClear.Tests.exe --startup-choice-hardware <directory>`：显式执行真实启动选择→确认→静音链路→主界面传递检查；不写真实设置、不安装驱动。

模型权重、推理参数、依赖版本与许可保持不变；v0.3.3 的 worker 增加阶段计时，运行时恢复及 DPI 修复见 [REPAIR-0.3.3.md](REPAIR-0.3.3.md)。本机真实链路以及隔离搬移可以验证，但全新电脑的驱动首次安装/修复、各种实体声卡及长时间游戏仍需实际验收；安装/UAC/重启异常分支使用替身测试。

设备选择框、悬停提示和主界面布局统一见 [界面与监听](COMPACT-UI.md)。安装状态与异常处理的维护记录见 [MAINTENANCE-20261115.md](MAINTENANCE-20261115.md)。
